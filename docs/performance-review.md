# Проверка производительности

## Что оптимизировано

- Цифровые PDF сначала читаются через PyMuPDF. Docling с OCR запускается только при
  недостаточном текстовом слое или большом количестве страниц без текста.
- DOCX и PPTX читаются нативными парсерами `python-docx` и `python-pptx`. Презентации и
  документы, состоящие преимущественно из изображений, переходят в OCR fallback.
- Проверка дубликатов и расчёт версий при загрузке пачки выполняются двумя SQL-запросами
  на всю пачку вместо двух запросов на каждый файл.
- Получение актуальной версии документов проекта выполняется PostgreSQL `DISTINCT ON`,
  без загрузки всей истории версий в приложение.
- Конспекты больших пачек для смыслового анализа обрабатываются с ограниченной
  конкурентностью. Значение по умолчанию — 2, максимум — 8.
- CPU-модель faster-whisper по умолчанию изменена с `large-v3` на `small`.
- Тяжёлые Python/ML-зависимости вынесены в отдельные кэшируемые слои Dockerfile. Изменение
  прикладного кода больше не заставляет устанавливать их заново.

## Контрольный замер

На одном и том же цифровом PDF из тестовой папки проекта (8 страниц):

| Реализация | Время | Извлечено символов |
|---|---:|---:|
| Docling + OCR до оптимизации | 673,6 с | 38 100 |
| PyMuPDF после оптимизации | 0,257 с | 29 436 |

Ускорение на этом файле — примерно в 2600 раз. Это локальный замер на конкретной машине,
а не гарантированный SLA. Нативное извлечение тестовых DOCX/PPTX занимало менее 0,2 с на
файл.

Чистая Docker-сборка после изменения зависимостей заняла 453,6 с. Немедленная повторная
сборка с тем же набором зависимостей заняла 4,28 с благодаря разделению слоёв.

## Оставшиеся ограничения

- Сканированные PDF, изображения и аудио остаются CPU-bound. Для больших объёмов нужен
  отдельный worker с GPU и GPU-сборка PyTorch/CTranslate2.
- Один процесс сейчас последовательно извлекает документы одного запуска. Это намеренно
  ограничивает пиковое потребление памяти Docling. Для горизонтального масштабирования
  следующий шаг — отдельная очередь заданий и несколько worker-процессов с блокировкой
  задания в PostgreSQL или внешним брокером.
- `storage/` является локальным файловым хранилищем. Для нескольких backend-инстансов его
  нужно заменить общим S3-совместимым хранилищем.
- Быстрый путь не извлекает сложную геометрию таблиц из PDF. Для классификации проекта
  используется текстовый слой; сканы и документы без достаточного текста автоматически
  переходят в Docling.
