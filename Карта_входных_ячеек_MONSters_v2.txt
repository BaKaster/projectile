КАРТА ВХОДНЫХ ЯЧЕЕК MONSTERS V2
================================

Книга назначения:
Универсальный_расчет_стоимости_MONSters_v2.xlsx

Назначение файла:
точная схема передачи данных из приложения / ИИ в Excel.

ВАЖНО:
1. Записывать данные только в перечисленные входные ячейки.
2. Не заменять формулы в расчетных столбцах.
3. После записи открыть книгу через Microsoft Excel и выполнить полный пересчет.
4. Проценты передавать десятичной долей: 20% = 0.20; 7% = 0.07.
5. Даты передавать как дату Excel; исходный строковый формат рекомендуется YYYY-MM-DD.

3. ДИНАМИЧЕСКИЕ ПАРАМЕТРЫ ВЫБРАННОГО ТИПА
==========================================

Сначала записать project_type_code в Ввод!B5.
Excel подставит названия и правила 8 параметров из листа «Параметры типов».

Внешнее значение слота 1                  -> Ввод!D20
Внешнее значение слота 2                  -> Ввод!D21
Внешнее значение слота 3                  -> Ввод!D22
Внешнее значение слота 4                  -> Ввод!D23
Внешнее значение слота 5                  -> Ввод!D24
Внешнее значение слота 6                  -> Ввод!D25
Внешнее значение слота 7                  -> Ввод!D26
Внешнее значение слота 8                  -> Ввод!D27

НЕ записывать во Ввод!B20:C27 и Ввод!E20:H27: там находятся подписи,
значения по умолчанию, принятые значения и формулы.

Коды влияния динамических параметров:

QTY             количество; множитель для базы «На единицу»
TERM_MONTHS     срок договора; множитель ежемесячных работ и затрат
COMPLEXITY      коэффициент сложности; умножает трудозатраты
RISK_PCT        резерв риска; добавляется к расчетным часам
PARALLEL_FTE    параллельная команда; уменьшает расчетный срок
LEAD_DAYS       срок поставки / доступов; добавляется к сроку проекта
MARKUP          наценка внешних затрат
TARGET_MARGIN   целевая маржа внешних затрат
INFO            справочный контекст; напрямую формулы не изменяет

Нельзя жестко связывать смысл параметра с номером слота.
Для каждого project_type_code нужно читать соответствующие 8 строк листа
«Параметры типов» и сопоставлять по полю «Код влияния».


4. ТРУДОЗАТРАТЫ И ПЛАН РАБОТ
=============================

Емкость: 100 работ, строки Excel с 6 по 105.

Правило адресации:

ExcelRow = 6 + index, где index начинается с 0.

Пример:

work_items[0] -> строка 6
work_items[1] -> строка 7
work_items[99] -> строка 105

Поля одной работы:

work_items[i].stage_no                     -> Расчёт!A{ExcelRow}
work_items[i].stage_name                   -> Расчёт!B{ExcelRow}
work_items[i].work_no                      -> Расчёт!C{ExcelRow}
work_items[i].work_name                    -> Расчёт!D{ExcelRow}
work_items[i].role                         -> Расчёт!E{ExcelRow}
work_items[i].estimated_hours              -> Расчёт!F{ExcelRow}
work_items[i].hours_basis                  -> Расчёт!G{ExcelRow}
work_items[i].quantity_override            -> Расчёт!H{ExcelRow}
work_items[i].sale_rate_override           -> Расчёт!I{ExcelRow}
work_items[i].cost_rate_override           -> Расчёт!J{ExcelRow}
work_items[i].site_or_contour              -> Расчёт!U{ExcelRow}
work_items[i].comment                      -> Расчёт!V{ExcelRow}

Обязательные поля строки:

- work_name: непустой текст. Пустое Расчёт!D отключает расчет всей строки.
- role: точная роль из справочника либо строка, содержащая #код роли.
- estimated_hours: число больше нуля.

Рекомендуемые поля для корректной группировки:

- stage_no
- stage_name
- work_no

Допустимые hours_basis:

Авто
Всего
В месяц
На единицу
Ед. × месяц

Ручные переопределения:

- quantity_override используется для баз «На единицу» и «Ед. × месяц».
- sale_rate_override имеет приоритет над ставкой продажи из справочника.
- cost_rate_override имеет приоритет над себестоимостью из справочника.

НЕ записывать в Расчёт!K:T.
Расчёт!K:T содержит внутренние формулы: код роли, ставки, базу, множитель,
расчетные часы, цену, себестоимость, рабочие дни и контроль строки.

Ограничение итогового листа:

- общий расчет учитывает все заполненные строки 6:105;
- разбивка «Итоги по этапам» отображает только этапы с номерами 1..20.

Правило для документа «этапа.docx»:

- переносить только строки с конкретной работой;
- строки «Итого по этапу» и «ИТОГО ПО ПРОЕКТУ» НЕ переносить;
- роль вида «L3 Windows инженер · #479» нормализовать к точной записи
  справочника «L3 Windows инженер | #479»;
- технически формула ищет код после символа #, но точная запись лучше
  проходит проверку списка Excel.

11. ДАННЫЕ MVP, ДЛЯ КОТОРЫХ В EXCEL НЕТ ОТДЕЛЬНЫХ ЯЧЕЕК
========================================================

Из документа «Требования к MVP продукта_v2 (2).docx» следует, что приложение
должно хранить больше данных, чем принимает текущая расчетная книга.

В Excel нет полноценных отдельных полей для:

- самих загруженных документов и их файловых идентификаторов;
- аналитической сводки тендера / запроса;
- предмета закупки;
- срока подачи заявки и иных тендерных дат;
- квалификационных критериев;
- полного списка уточняющих вопросов;
- ответов пользователя на вопросы;
- истории автоматического расчета и экспертных версий;
- автора, согласующего и статуса утверждения;
- связи с проектом-прецедентом;
- объяснений ИИ и ссылок на фрагменты исходных документов;
- истории изменений ставок и методики.

Эти данные должны храниться в базе приложения. В Excel можно передать только:

- краткое обозначение источника / версии в Ввод!B14;
- главное допущение в Ввод!B15;
- четыре ключевых вопроса / риска в Ввод!A36:D39;
- комментарии по отдельным работам в Расчёт!V6:V105.


12. РЕКОМЕНДУЕМЫЙ ПОРЯДОК ЗАГРУЗКИ
===================================

1. Сделать копию чистого Excel-шаблона для нового проекта.
2. Очистить старые повторяемые входные данные:
   - Ввод!D20:D27;
   - Ввод!A36:D39;
   - Расчёт!A6:J105 и Расчёт!U6:V105;
   - Внешние затраты!A6:G25 и Внешние затраты!K6:K25.
3. Ввод!B4:B16 либо полностью перезаписать валидным общим payload, либо
   сохранить значения по умолчанию чистого шаблона. Не оставлять пустыми
   Ввод!B7:B9, Ввод!B11, Ввод!B13 и Ввод!B16 без осознанной причины.
4. Не очищать формулы в Расчёт!K:T и Внешние затраты!H:J.
5. Записать project_type_code в Ввод!B5.
6. Пересчитать книгу, чтобы получить структуру параметров выбранного типа.
7. Записать общие и динамические параметры.

ПРЕДУПРЕЖДЕНИЕ О ДЕМОНСТРАЦИОННОЙ ПРОВЕРКЕ:

Проверки!B14 сравнивает сумму исходных часов с фиксированным значением 88.
Для любого другого проекта это даст WARN. WARN не переводит общий MODEL STATUS
в FAIL, но эту проверку нужно убрать или параметризовать для промышленной версии.
